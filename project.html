Implementation & project takeaways

The project uses Terraform to provision a VPC in eu-west-2, distribute application instances across two private subnets, and place public-facing and administrative entry points in public subnets.

01 · Networking

Public edge, private application tier.

The VPC uses CIDR 10.0.0.0/16. Public subnets are 10.0.1.0/24 in eu-west-2a and 10.0.2.0/24 in eu-west-2b; private subnets are 10.0.3.0/24 and 10.0.4.0/24.

Public routing uses an Internet Gateway. Private routing uses a NAT Gateway placed in the first public subnet.

provider "aws" {
  region = "eu-west-2"
}

resource "aws_vpc" "main" {
  cidr_block = "10.0.0.0/16"
}
02 · Traffic & compute

Load balanced and horizontally scalable.

The ALB listens on HTTP port 80 and forwards requests to a target group. The launch template uses a t2.micro instance and installs Apache; the Auto Scaling Group spans both private subnets.

03 · Database & access

Multi-AZ RDS with a defined subnet group.

The database uses MySQL on db.t3.micro with 20 GB allocated storage and Multi-AZ enabled. Its subnet group explicitly targets the two private subnets.

The project also uses a bastion host in the first public subnet for SSH access. The original configuration restricts SSH to a single /32 source address; that address is intentionally not reproduced here.

resource "aws_db_instance" "db" {
  engine            = "mysql"
  instance_class    = "db.t3.micro"
  allocated_storage = 20
  multi_az          = true
  skip_final_snapshot = true
  db_subnet_group_name =
    aws_db_subnet_group.db_subnet_group.name
}
04 · Post-project takeaways

Issues found and changes made.

Final snapshot on destroy

Terraform destroy initially failed because RDS defaults to requiring a final snapshot. For this basic project, skip_final_snapshot = true was added.

Default DB subnet group

The initial RDS setup fell back to a broken default subnet group that referenced a deleted VPC. Creating an explicit DB subnet group fixed the issue.

Secret handling

The project notes that a real-world structure should be modular and that the database password should use secret injection such as AWS Secrets Manager rather than a tfvars file.

Portfolio adjustment: the hard-coded database credential shown in the source document is deliberately excluded from this site. The site preserves the project lesson without publishing the secret.
